# KTin 2.7.14

> 현재 버전: **2.7.14** — TinTin++ 트리거 파일을 BOM 없이 저장하고, 트리거 편집기에서 파일 불러오기·다른 이름 저장·주소록 연결을 지원합니다.


## 2.7.14 트리거 파일 로딩·저장·화면 수정

- KTin 트리거 파일을 **UTF-8 BOM 없이** 저장합니다. 파일 첫 바이트가 `#`(16진수 `23`)가 되므로 TinTin++의 `#read`가 BOM을 명령 문자로 오인하지 않습니다.
- 트리거 편집기 배경·글자·입력칸·트리·버튼을 현재 KTin ANSI 테마에 맞춰 표시합니다.
- 상단에 `파일 불러오기...`, `다른 이름 저장...`, `주소록에 현재 파일 지정` 버튼을 추가했습니다.
- 주소록 스크립트가 비어 있으면 임의의 `triggers\ktin_<호스트>_<ID>.tin`을 만들지 않고 기본 `ktin_triggers.tin`을 주소록에 지정합니다.
- 파일을 불러와 편집만 할 수도 있고, 명시적으로 현재 주소록의 접속 스크립트로 지정할 수도 있습니다.
- `ktin_c_<고유번호>`는 파일명이 아니라 한글 폴더를 TinTin++에서 묶기 위한 내부 Class 이름임을 화면에 안내합니다.
- 프로그램 및 Windows 리소스 버전을 `2.7.14` / `2.7.14.0`으로 갱신했습니다.

## 2.7.13 폴더/Class 기반 TinTin++ 트리거 편집기

- `편집 → 트리거 편집(&A)...` 메뉴를 추가했습니다.
- Mudlet과 비슷한 트리 구조에서 폴더, 하위 폴더, 트리거를 추가·수정·삭제·정렬할 수 있습니다.
- 폴더와 트리거를 각각 켜고 끌 수 있으며, 상위 폴더를 끄면 하위 폴더와 트리거도 생성하지 않습니다.
- 한글 폴더명은 편집 화면에 그대로 표시하고 TinTin++ 내부 Class는 `ktin_c_<영문/숫자 ID>`로 안전하게 생성합니다.
- 한글 이름과 폴더 구조는 별도 INI 대신 해당 `.tin` 파일의 KTin 관리 메타데이터에 UTF-8로 보존합니다.
- 주소록으로 접속한 상태에서 편집기를 열면 그 주소록의 스크립트 파일을 편집합니다. 스크립트가 비어 있으면 `triggers\ktin_<호스트>_<ID>.tin`을 만들고 `sessions.ini`의 주소록 항목에 자동 연결합니다.
- 주소록 접속 시 `main.tin` 다음에 해당 주소록 스크립트가 그 세션에만 로드되도록 `#session`의 스크립트 인수를 사용합니다.
- 주소록 세션이 없으면 전역 기본 파일 `ktin_triggers.tin`을 편집하며, 이 파일이 있으면 TinTin++ 시작 직후 ConPTY로 `#read {ktin_triggers.tin}`을 자동 전송합니다.
- 저장 전 기존 파일은 `.bak`으로 백업하고 `.tmp` 파일을 통한 원자 교체를 사용합니다.
- KTin 관리 구역 밖의 기존 사용자 스크립트는 그대로 보존하며, 편집 트리에는 KTin 관리 구역의 항목만 표시합니다.
- 폴더를 삭제한 뒤 다시 읽어도 이전 Class를 먼저 정리하여 삭제된 트리거가 현재 세션에 남지 않습니다.
- 프로그램 및 Windows 리소스 버전을 `2.7.13` / `2.7.13.0`으로 갱신했습니다.

## 2.7.12 주소록 Enter 연결 수정

- `Alt+A`로 주소록을 연 뒤 위·아래 방향키로 주소를 선택하고 Enter를 누르면 연결됩니다.
- 리스트뷰의 Enter 알림(`NM_RETURN`)을 더블클릭과 같은 접속 동작으로 처리합니다.
- 주소록을 열 때 첫 주소가 기본 선택되므로, 목록이 하나뿐이면 바로 Enter로 접속할 수 있습니다.
- 더블클릭·Enter·연결 버튼이 하나의 공통 연결 함수를 사용합니다.
- 프로그램 및 Windows 리소스 버전을 `2.7.12` / `2.7.12.0`으로 갱신했습니다.

## 2.7.11 서버 수신 문구 즉시 표시 수정

ConPTY 출력 읽기 스레드는 빠른 출력 중 UI 메시지를 줄이기 위해 50ms 단위로 갱신을 묶었습니다. 그러나 `ReadFile()`이 블로킹 방식이어서, 마지막 출력 조각이 직전 갱신 후 50ms 안에 도착하면 알림을 보류한 채 다음 데이터를 기다렸습니다. 그 결과 서버는 이미 이름 확인 질문을 보냈는데도 KTin에서는 다음 Enter나 다음 서버 출력이 올 때까지 3~6초 늦게 보일 수 있었습니다.

- 줄바꿈 없는 로그인 질문과 일반 프롬프트를 수신 즉시 UI에 알림
- 같은 시점에 여러 조각이 들어올 때는 원자 플래그로 UI 메시지를 한 개만 유지
- 기존 UI 30ms 다시 그리기 타이머는 유지하여 빠른 전투 출력의 paint 호출을 계속 묶음
- 다른 MUD 클라이언트와 동일하게 서버가 보낸 질문을 즉시 확인 가능
- 프로그램 및 Windows 리소스 버전을 `2.7.11` / `2.7.11.0`으로 갱신


## 2.7.10 도움말 열 정렬·스크롤 잔상 수정

- 단축키·메뉴명 첫 열이 내용창 가운데까지 밀리던 문단 시작 들여쓰기를 제거했습니다.
- 키·메뉴명은 구역 제목 아래에서 한 단계만 들여쓰고, 설명은 고정된 둘째 열에 맞춥니다.
- `기본 / 전체 단축키`, `파일 메뉴 / 연결`, `편집 메뉴`, `보기 메뉴`, `입력창 사용법`, `로그창 / 선택 / 복사`, `단축버튼 / 기능키`, 메모장 및 파일 위치 페이지에 동일한 열 규칙을 적용했습니다.
- 원문에 있는 2칸·4칸 단계 공백과 RichEdit 문단 들여쓰기가 이중 적용되던 문제를 없앴습니다.
- 도움말을 마우스 휠·스크롤바·PageUp/PageDown으로 움직일 때 하단에 이전 문단이 잔상으로 남는 문제를 전체 다시 그리기로 보완했습니다.
- 프로그램 및 Windows 리소스 버전을 `2.7.10` / `2.7.10.0`으로 갱신했습니다.

## 2.7.9 정보창 버전·도움말 문단 서식 수정

- 정보창이 패치 번호를 무시하고 빌드 번호를 두 자리로 출력하여 `2.7.8`을 `2.7.00`으로 표시하던 문제 수정
- 정보창, 메인창 제목, 트레이 설명과 도움말 제목이 `app_version.h`의 같은 버전 문자열을 사용하도록 통일
- 도움말 본문에서 제목·구역·키·설명을 여러 색으로 표시하지 않고 한 가지 글자색만 사용
- 제목과 구역 구분은 글자 크기와 굵기로만 표현하여 ANSI 색상 문서처럼 보이던 현상 제거
- RichEdit 문단 위치 계산을 CR 한 글자 기준으로 맞춰 뒤쪽 구역 제목에 앞 문단의 들여쓰기가 잘못 이어지던 문제 수정
- `[연결과 프로그램]`, `[입력창과 화면]`, `[사용자 지정]`처럼 같은 단계의 구역 제목은 모두 같은 첫 열에서 시작


## 2.7.8 도움말 열 정렬·줄바꿈 정리

도움말의 키와 설명은 더 이상 여러 개의 공백으로 위치를 맞추지 않습니다. RichEdit의 실제 탭 위치와 내어쓰기를 사용하므로 가변폭 글꼴에서도 키 열과 설명 열이 일정하게 정렬됩니다.

- 키·메뉴명은 왼쪽 열, 설명은 고정된 오른쪽 열에 표시
- 긴 설명이 자동 줄바꿈되면 오른쪽 설명 열 아래로 이어짐
- 제목·부제·구역 제목·본문의 크기, 색상, 문단 간격 통일
- 기본 도움말 창 확대, 사용자가 크기 조절·최대화 가능
- 도움말 제목의 버전을 `app_version.h`에서 자동 표시
- 체력 막대 설명을 현재 구조인 `Looming.Vitals` 또는 일반 텍스트 프롬프트 분석으로 갱신


## 2.7.7 ANSI 변환 보기 빈행 수정

메모장의 `ANSI 변환 보기`에서 화면 지우기용 SGR/CSI 코드만 남은 행을 실제 문자 행으로 오인하여 전투 메시지 사이에 빈행이 추가되던 문제를 수정했습니다. `ANSI 코드 제거`와 `ANSI 변환 보기`가 같은 논리 행 구조를 사용하므로 인게임 출력과 동일한 줄 간격을 유지합니다.


## 2.7.6 재접속 화면 보존·갈무리 형식·빈행 정리

2.7.5는 `ESC[2J`가 도착한 순간의 화면만 스크롤 기록으로 보존했습니다. 일부 서버와 TinTin++ 출력은 `ESC[2J`보다 먼저 여러 `ESC[K`와 커서 이동으로 현재 화면을 지우기 때문에, 마지막 전투·사망·세션 종료 내용이 이미 사라진 뒤 스냅샷되는 경우가 있었습니다.

2.7.6은 다음 세 경계에서 화면을 먼저 보존합니다.

- TinTin++의 세션 종료·연결 실패 문구 수신 직후
- 자동 재접속 명령을 보내기 직전
- 접속 성공 문구 뒤 새 로그인 화면을 지우기 직전

같은 화면을 세 경계에서 반복 보존하더라도 히스토리 끝과 비교해 중복 스냅샷은 추가하지 않습니다.

갈무리에는 `코드 갈무리`와 `일반 갈무리`가 추가되었습니다.

- **코드 갈무리**: 기존 방식처럼 ANSI/OSC/커서 제어 바이트까지 원형 저장 (`*_ansi.txt`)
- **일반 갈무리**: ANSI 제어 코드를 제외하고 실제 문자만 UTF-8로 저장 (`*_plain.txt`)
- 갈무리 켜짐/꺼짐과 관계없이 형식을 미리 바꿀 수 있음
- 갈무리 중 형식을 바꾸면 서로 다른 형식이 한 파일에 섞이지 않도록 새 파일을 시작

메모장 `편집 → 연속되는 빈행 삭제`는 일반 빈행과 `ESC[K` 같은 ANSI 지우기 코드만 있는 행을 모두 빈행으로 판단하여 연속 구간을 한 행으로 줄입니다.


## 2.7.5 재접속 화면 지우기 전 스크롤 기록 보존

TinTin++ 또는 서버가 재접속·로그인 화면을 시작하면서 보내는 `ESC[2J`는 현재 터미널 화면을 지웁니다. 이전 버전은 이 명령을 처리할 때 현재 화면을 스크롤 기록으로 옮기지 않아, 전투 직후 연결이 끊기고 자동 재접속하면 화면에 있던 마지막 전투 내용과 세션 종료·재접속 메시지가 PageUp에서도 사라질 수 있었습니다.

2.7.5부터는 `ESC[2J` 처리 직전에 현재 화면의 실제 내용이 있는 행을 스크롤 기록으로 보존한 뒤 새 화면을 지웁니다.

- 마지막 전투 출력과 체력 변화 보존
- 세션 종료, `#zap`, 재접속 시도 및 접속 성공 메시지 보존
- PageUp/PageDown으로 이전 화면 확인 가능
- 문자색·배경색·굵기·한글 전각 셀 보존
- 화면 위아래의 완전히 빈 행은 제외
- 연속된 빈 `ESC[2J`는 중복 기록하지 않음
- 갈무리 원시 로그 저장 방식은 기존과 동일하게 유지

> 이 변경은 KTin 화면 버퍼의 보존 문제를 수정합니다. 서버가 사망 메시지를 보내기 전에 연결을 종료하는 문제는 Sector_D의 사망 처리 순서를 별도로 확인해야 합니다.


## 2.7.4 서버 프롬프트 원문 복원

KTin은 더 이상 `Looming.Cursor` 값을 지연시간 뒤에 강제로 터미널에 그리지 않습니다. 함께 제공되는 TinTin++ 수정본은 `Core.Supports.Set`에서 `Looming.Cursor`만 제외합니다. Sector_D는 Cursor 지원이 없으면 기존 `write_prompt()` 경로로 일반 텍스트 프롬프트를 보내므로, 방 설명·물건·NPC·명령 결과가 끝난 실제 서버 전송 위치에 프롬프트가 그대로 표시됩니다.

- 빈 Enter, 이동, `봐`, `누구`, `점수` 뒤의 프롬프트를 서버 전송 순서 그대로 표시
- 120ms 대기, 출력 끝 추측, KTin 강제 프롬프트 삽입 기능 완전 제거
- 일반 텍스트 `[ 체력/최대체력,정신력/최대정신력 <명령수> ]`를 화면 출력과 별도로 관찰하여 체력·정신력 막대 갱신
- `Looming.Vitals` 지원은 계속 알리며, 서버가 Vitals JSON을 보내는 경우에도 동일한 막대 갱신
- `Looming.Map`, `Room`, `Char`, `Combat`, `Party`, `System`, `Info`, `Chat`, `Term` GMCP 기능은 그대로 유지
- 2.7.2와 2.7.3에서 사용한 Cursor 강제 출력 방식은 폐기

> 이 변경은 KTin과 TinTin++를 함께 교체해야 완성됩니다. 이전 TinTin++가 `Looming.Cursor`를 계속 광고하면 Sector_D가 일반 프롬프트를 생략할 수 있습니다.

KTin은 TinTin++를 Windows GUI에서 사용할 수 있도록 만든 한국어 MUD 클라이언트 래퍼입니다. TinTin++의 세션·스크립트·매크로 기능을 유지하면서 고정폭 ANSI 터미널, 3줄 입력창, 주소록, 갈무리, 메모장, GMCP 지도/상태, 접근성용 화면 키패드와 보조창 도킹을 제공합니다.

이 문서는 과거의 `README_SAFE*`, `README_BUILD_WSL.md`, `README_BUILD_FIX10~36.txt` 내용을 모두 통합한 유일한 README입니다. 이전 README 파일은 중복과 버전 혼동을 막기 위해 제거했습니다.

## 빠른 시작

1. `ktin.exe` 옆 `bin\tt++.exe`가 있는지 확인합니다.
2. KTin을 실행합니다.
3. `파일 → 빠른 연결` 또는 `Alt+Q`를 누릅니다.
4. 서버 주소, 포트, 문자셋을 선택해 접속합니다.
5. 자주 쓰는 서버는 `파일 → 주소록`에서 저장합니다.
6. 명령은 하단 입력창에 쓰고 Enter로 보냅니다.
7. 프로그램의 전체 사용법은 `도움말 → 단축키 도움말`에서 확인합니다.

## 입력창

입력창은 3줄이며 현재 입력과 가까운 명령 기록을 동시에 보여줍니다.

- Enter는 현재 줄을 전송합니다.
- 빈 줄에서 Enter를 누르면 서버로 빈 Enter를 보냅니다.
- 위·아래 키는 줄 사이를 이동하고 맨 위/아래에서는 기록을 탐색합니다.
- 줄 맨 앞의 Backspace는 이전 줄 끝으로 이동합니다. `Backspace 키로 삭제를 현재 행으로 제한`을 켜면 넘어가지 않습니다.
- 왼쪽·오른쪽도 줄 경계에서 인접 입력줄로 이동합니다.

### 여러 행 붙여넣기

한 줄 텍스트는 입력창에 붙습니다. 줄바꿈이 포함된 텍스트는 입력창에 넣지 않고 모든 줄을 즉시 TinTin++로 전송합니다.

- Windows CRLF, Unix LF, 단독 CR 지원
- 본문의 빈 줄 유지
- 마지막 줄에 엔터가 없어도 전송
- 클립보드 원문은 변경하지 않음

게시판 사용 예:

1. MUD에서 글쓰기 모드로 들어갑니다.
2. 외부 메모장에서 본문을 복사합니다.
3. 입력창에서 Ctrl+V를 누릅니다.
4. 본문 전체가 전송된 뒤 입력창에 `.`을 쓰고 Enter를 누릅니다.

## 로그창과 선택 영역

### 마우스

- 휠: 3줄씩 스크롤

- 왼쪽 드래그: 블럭 선택

### 블럭 선택 완료 동작

`옵션 → 환경 설정 → 기타 설정 → 블럭 설정 후`:

1. 반전선택 클립보드
2. 반전선택 코드로 클립보드
3. 반전선택 파일저장
4. 반전선택 코드로 파일저장
5. 선택메뉴 띄우기

선택메뉴에는 일반 복사·파일저장, ANSI 코드 복사·파일저장, 닫기가 있습니다.

### 일반 내보내기와 코드 내보내기

- 일반: 화면의 글자만 UTF-8 텍스트로 내보냅니다.
- 코드로: 셀의 글자색·배경색·굵기를 ANSI true-color SGR 코드로 재구성합니다.
- 일반 파일: UTF-8 BOM
- 코드 파일: ESC 바이트를 보존하는 UTF-8, BOM 없음
- 기본 저장 폴더: `실행폴더\저장`
- 기본 파일명: `YYYYMMDD_HHMMSS.txt`

## 주소록·빠른 연결·자동 로그인·재연결

### 주소록 항목

- 표시 이름
- 호스트
- 포트
- UTF-8 또는 EUC-KR/CP949
- TinTin++ 스크립트
- 아이디와 비밀번호
- 아이디/비밀번호 패턴 및 실패 패턴
- 연결 실패/끊김 시 자동 재연결
- 최근 접속 시간

비밀번호는 INI 안전 HEX 형태로 저장합니다.

### 창별 세션 분리

빠른 연결의 고정 이름이나 주소록 표시명을 실제 TinTin++ 세션명으로 재사용하지 않습니다. 프로세스 ID와 접속 순번을 조합한 내부 이름을 사용하므로 새 창의 자동 재연결이 기존 창의 서버로 연결되는 것을 방지합니다.

### 첫 접속 #zap 보호

처음 접속할 때 추적 중인 세션이 없으면 인자 없는 `#zap`을 보내지 않습니다. 사용자가 `파일 → 연결 끊기`를 선택했을 때만 현재 세션을 직접 종료합니다.

## 메모장

메모장은 `Alt+V`로 엽니다.

### 갈무리 로그 열기와 ANSI 보기

메모장 `파일` 메뉴에는 실행 폴더의 `log` 디렉터리를 바로 여는 **갈무리 폴더 열기**와,
0KB 파일을 제외하고 최근 수정 순으로 최대 5개를 고르는 **마지막 갈무리 열기**가 있습니다.

메모장 `특수` 메뉴의 ANSI 도구는 다음처럼 작동합니다.

- **ANSI 코드 제거**: CSI, OSC, DCS 등 터미널 제어 코드를 제거하고 편집 가능한 새 문서로 만듭니다. 화면 끝까지 채운 공백과 커서 이동을 함께 정리하여 입력 명령과 전투 메시지가 불필요하게 오른쪽으로 밀리지 않게 합니다. 원본 로그를 실수로 덮어쓰지 않도록 저장 시 새 파일명을 묻습니다.
- **ANSI 변환 보기**: 현재 ANSI 테마에 따라 글자색, 배경색, 굵기를 적용합니다. 녹색 ANSI 글자는 녹색으로 표시됩니다. 화면 재생용 커서 이동·지우기와 줄 끝 패딩을 정리하며, 화면 채움 공백에 붙은 ANSI 코드만 있는 행을 실제 글자 행으로 오인하지 않으므로 전투 메시지 사이에 원본에 없는 빈행이 추가되지 않습니다. 원본 보호를 위해 읽기 전용이며, 편집하려면 먼저 ANSI 코드 제거를 선택합니다.
- **현재 파일 닫기 (`Ctrl+W`)**: 메모장은 한 번에 한 문서만 표시합니다. ANSI 변환/제거 결과는 디스크 임시 파일이 아니라 메모리에서 유지되며, 이 메뉴로 현재 원본과 변환 상태를 모두 닫고 빈 문서로 돌아갑니다.
- **연속되는 빈행 삭제**: `편집` 메뉴에서 연속된 빈행을 한 행으로 줄입니다. 공백만 있는 행뿐 아니라 `ESC[K`처럼 ANSI 화면 지우기 코드만 있는 행도 빈행으로 계산하며, 연속된 `ESC[K` 행은 첫 한 행만 남깁니다.
- 화면 지우기, 커서 이동, 창 제목 변경 같은 비표시 터미널 명령은 화면에 문자로 표시하지 않습니다.

## 문제 해결

### `patch` 명령이 Windows CMD에서 안 됨

```bat
wsl bash -lc "cd /mnt/d/Tintin_gui/1 && patch --dry-run -p1 < 파일.patch"
wsl bash -lc "cd /mnt/d/Tintin_gui/1 && patch -p1 < 파일.patch"
```

Windows CMD의 줄 이어쓰기는 `\`가 아닙니다. 위처럼 한 줄로 실행합니다.

### 전각 지도에 빈 줄이 생김

`모호한 동아시아 문자 폭을 넓게 처리` 옵션을 서버 출력과 맞춥니다. KTin 2.7은 오른쪽 끝 채움 공백이 전각 문자 계산 차이로 빈 행이 되는 경우를 보정합니다.

### GMCP 창이 비어 있음

- GMCP 브리지 수정본 `tt++.exe`가 `bin`에 있는지 확인
- 서버가 해당 GMCP 모듈을 실제로 보내는지 확인
- 환경설정의 체크박스는 수신 요청이 아니라 표시 선택

### 새 창 자동 재연결이 다른 서버로 감

2.7 소스는 각 프로세스와 접속마다 고유 내부 세션명을 사용합니다. 과거 `tt++.exe`나 `ktin.exe`가 섞이지 않았는지 확인합니다.

### 빌드 후 실행 파일이 바뀌지 않음

```bat
dir /s /od D:\Tintin_gui\1\*.exe
```

가장 최근 `ktin.exe`를 실행·배포합니다.

### C++ `std::max`에서 LONG/int 오류

Windows의 `RECT`, `TEXTMETRIC` 값은 `LONG`일 수 있습니다. `static_cast<int>`로 같은 형식으로 맞춰야 합니다. 2.7 소스에는 현재 알려진 GMCP 관련 형식 수정이 포함되어 있습니다.

- TinTin++가 Sector_D의 GMCP 협상을 수락하고 Core.Hello/Core.Supports.Set을 전송합니다.
- 수신 GMCP는 화면에 보이지 않는 OSC 777 브리지로 KTin에 전달됩니다.
- 보기 메뉴에 `GMCP 지도 보기`, `GMCP 정보 보기`가 추가됩니다.
- Looming.Map의 zone/lines를 별도 지도 창에 실시간 표시합니다.
- 지도 방 기호를 클릭하면 지도 연결선을 분석해 이동 명령을 한 칸씩 보냅니다.
  다음 Looming.Map이 도착한 뒤에만 다음 명령을 보내므로 명령을 한꺼번에 밀어 넣지 않습니다.
- 이동 중 전투 등으로 새 지도 정보가 오지 않으면 자동으로 멈추며 `다시 시도` 또는 `이동 취소`를 사용할 수 있습니다.
- GMCP 정보 창은 Looming.Vitals의 체력/정신력과 Party/Combat/System 등 최신 JSON을 표시합니다.
- Sector_D 소스와 JSON 생성 방식은 변경하지 않습니다.

KTin WSL 빌드
===================

WSL에서 MinGW-w64 교차 컴파일러로 Windows용 ktin.exe를 만든다.

1. WSL에 빌드 도구 설치

   sudo apt update
   sudo apt install -y build-essential mingw-w64

2. 빌드

   cd ~/ktin
   make

3. 결과 파일

   ktin.exe

4. 실행 시 DLL 오류가 날 때

   libgcc_s_seh-1.dll 또는 libstdc++-6.dll 오류는 MinGW 런타임 DLL을
   찾지 못해서 생긴다.
   이 Makefile은 해당 런타임을 정적 링크하도록 설정.
   기존 ktin.exe가 있다면 make clean 후 다시 빌드.

5. 리소스 빌드가 실패할 때

   make clean
   make nores

6. 컴파일러 확인

   x86_64-w64-mingw32-g++ --version
   x86_64-w64-mingw32-windres --version

7. 빌드 산출물 정리

   make clean

   clean은 ktin.exe, *.o, *.obj, *.res, *.aps 파일을 삭제한다.

KTin WSL 빌드
===================

WSL에서 MinGW-w64 교차 컴파일러로 Windows용 ktin.exe를 만든다.

1. WSL에 빌드 도구 설치

   sudo apt update
   sudo apt install -y build-essential mingw-w64

2. 빌드

   cd ~/ktin
   make

3. 결과 파일

   ktin.exe

4. 실행 시 DLL 오류가 날 때

   libgcc_s_seh-1.dll 또는 libstdc++-6.dll 오류는 MinGW 런타임 DLL을
   찾지 못해서 생긴다.
   이 Makefile은 해당 런타임을 정적 링크하도록 설정.
   기존 ktin.exe가 있다면 make clean 후 다시 빌드.

5. 리소스 빌드가 실패할 때

   make clean
   make nores

6. 컴파일러 확인

   x86_64-w64-mingw32-g++ --version
   x86_64-w64-mingw32-windres --version

7. 빌드 산출물 정리

   make clean

   clean은 ktin.exe, *.o, *.obj, *.res, *.aps 파일을 삭제한다.

- GMCP room.info의 zone 값을 지역명으로 사용합니다.
- Windows 파일명에 사용할 수 없는 문자는 밑줄(_)로 바꿉니다.
- 지역명이 비어 있으면 GMCP지도.txt로 저장합니다.
- UTF-8 BOM 형식으로 저장합니다.

--------------------

- 트리거 편집기와 같은 주소록 스크립트 파일(.tin)을 사용합니다.
- 별도 KTin 관리 구역만 추가/교체하므로 기존 수동 스크립트와 트리거 관리 구역은 보존합니다.
- 폴더/하위 폴더/CLASS/사용 여부를 트리거 편집기와 같은 방식으로 관리합니다.

  · 이름
  · 사용
  · CLASS
  · 인식 패턴

4. TinTin++ 저장 구문
---------------------

    #highlight {인식 패턴} {색상 지정} {우선순위}

예:

    #highlight {경험치를 얻었습니다} {Red} {5}
    #highlight {위험} {White b red} {5}
    #highlight {중요 알림} {reverse} {5}

- 배경색은 색상 지정 안에서 b 다음에 기록합니다.
- 반전은 reverse로 기록합니다.
- 직접 선택한 RGB 색상은 TinTin++의 <rgb> 형식으로 변환합니다.

KTin 2.7.13 - 폴더/Class 기반 TinTin++ 트리거 편집기 구현 안내
====================================================================

1. 구현 목적
-----------
KTin은 트리거를 자체 실행하지 않고, 주소록에 연결된 TinTin++ .tin 파일을
편집하는 역할만 담당합니다. 실제 문자열 인식과 명령 실행은 TinTin++의
#action 및 #class 기능이 처리합니다.

메뉴 위치:
  편집 -> 트리거 편집(&A)...

2. TinTin++ 로드 순서
--------------------
가. KTin 시작
  process_manager.cpp의 기존 StartTinTinProcess()가 다음과 같이 실행합니다.

    bin\tt++.exe main.tin

  따라서 main.tin이 가장 먼저 읽힙니다.

나. 주소록으로 접속
  address_book.cpp의 ConnectAddressBookEntry()가 주소록의 스크립트 경로를
  #session 명령의 네 번째 인수로 넘깁니다.

    #session {내부세션명} {서버주소} {포트} {주소록스크립트.tin}

  주소록 스크립트는 접속에 성공한 해당 TinTin++ 세션에서 읽힙니다.
  다른 주소록 세션의 전용 트리거가 섞이는 것을 피하기 위해, 접속 전에
  전역 #read로 주입하는 대신 #session의 파일 인수를 사용했습니다.

다. 주소록 세션이 없는 상태
  편집기는 KTin 실행 폴더의 ktin_triggers.tin을 대상으로 합니다.
  이 파일이 이미 있으면 TinTin++ 백엔드가 시작된 직후 ConPTY 입력으로
  다음 명령을 자동 전송합니다.

    #read {ktin_triggers.tin}

  main.tin은 프로세스 시작 인수로 먼저 처리되므로, 이 파일은 main.tin 뒤에
  읽힙니다. 이 전역 파일의 트리거는 TinTin++ 시작 세션에서 정의되므로
  이후 세션에 상속될 수 있습니다. 주소록마다 완전히 분리할 트리거는 반드시
  주소록별 스크립트 파일에 작성하십시오.

3. 주소록 스크립트 자동 생성
---------------------------
현재 주소록으로 접속했거나 접속 예약 중인 상태에서 트리거 편집기를 열었는데
그 주소록의 스크립트 경로가 비어 있으면 다음 형식의 파일을 자동 지정합니다.

  triggers\ktin_<서버주소>_<8자리ID>.tin

예:
  triggers\ktin_mud.example.com_A1B2C3D4.tin

자동 생성 파일명은 TinTin++의 Windows 파일 처리와 로캘 차이를 피하기 위해
ASCII 문자만 사용합니다. 주소록의 한글 이름은 sessions.ini에 그대로 남습니다.
새 경로는 즉시 sessions.ini의 해당 주소록 항목에 저장됩니다.

4. 폴더와 TinTin++ Class 연결
----------------------------
편집 화면의 폴더 이름은 한글을 그대로 지원합니다. TinTin++ 내부 Class 이름은
한글 지원 여부와 무관하게 다음처럼 안전한 ASCII ID를 사용합니다.

  ktin_c_0123456789ABCDEF

한글 표시 이름, 상하위 폴더 관계, 사용 여부, 트리거 이름/패턴/명령/우선순위는
별도 INI 파일이 아니라 같은 .tin 파일의 #NOP 메타데이터에 UTF-8로 저장됩니다.

관리 구역 예:

  #NOP {KTIN_TRIGGER_EDITOR_BEGIN|1}
  #NOP {KTIN_KNOWN_CLASS|0123456789ABCDEF}
  #NOP {KTIN_FOLDER|0123456789ABCDEF||1|<한글이름 UTF-8 HEX>}
  #NOP {KTIN_TRIGGER|...}
  #NOP {KTIN_TRIGGER_RUNTIME_BEGIN}
  #class {ktin_c_0123456789ABCDEF} {kill}
  #class {ktin_c_0123456789ABCDEF} {open}
  #action {인식 패턴} {실행 명령} {5}
  #class {ktin_c_0123456789ABCDEF} {close}
  #NOP {KTIN_TRIGGER_RUNTIME_END}
  #NOP {KTIN_TRIGGER_EDITOR_END}

폴더를 끄면 그 폴더와 모든 하위 폴더의 #action을 생성하지 않습니다.
다시 읽을 때는 과거 KTin Class를 먼저 kill한 뒤 현재 켜진 폴더만 다시 만듭니다.
폴더를 삭제한 경우에도 옛 Class ID를 정리 목록에 남겨 현재 세션에 이전
트리거가 잔류하지 않게 했습니다.

6. 기존 .tin 파일 보존 방식
--------------------------
KTin은 다음 두 표식 사이만 다시 작성합니다.

  ...
  #NOP {KTIN_TRIGGER_EDITOR_END}

표식 앞뒤에 사용자가 직접 작성한 alias, variable, event, action, 주석 등은

중요한 제한:

  트리로 가져오지 않습니다. 편집 화면에는 KTin 관리 구역에서 만든 항목만
  나타납니다. 기존 #action을 GUI에서 관리하려면 편집기에서 새 트리거로
  옮긴 뒤 원래 줄을 직접 정리해야 합니다.

KTin 2.7.14 - TinTin++ 트리거 파일 로딩/저장 및 BOM 수정 안내
=================================================================

수정 목적
---------
1. KTin이 만든 .tin 파일이 UTF-8 BOM(EF BB BF)으로 시작하여 TinTin++가
   다음 오류를 내던 문제를 수정합니다.

   #오류: #READ {ktin_triggers.tin}: 파일 시작 문자가 올바르지 않습니다 '?'.

2. 트리거 편집 창이 KTin의 어두운 ANSI 테마와 무관하게 흰색으로 보이던
   문제를 수정합니다.

3. 기본 ktin_triggers.tin뿐 아니라 사용자가 선택한 다른 .tin 파일도
   불러오고 다른 이름으로 저장할 수 있게 합니다.

4. 현재 편집 파일을 주소록의 접속 스크립트로 명시적으로 지정할 수 있게
   합니다.

핵심 변경
---------
- trigger_editor.cpp의 SaveTriggerModel()은 WriteUtf8NoBomTextFile()을 사용합니다.
- utils.cpp / utils.h에 WriteUtf8NoBomTextFile()이 추가되어 있습니다.
- 저장되는 파일의 첫 바이트는 '#'의 16진수 값인 23입니다.
- 파일에 기존 UTF-8 BOM이 있어도 편집기에서 저장하면 BOM이 제거됩니다.
- 팝업 배경, 정적 글자, 입력칸, 트리, 버튼을 현재 ANSI 테마에 맞춥니다.
- 트리거 편집기 상단에 다음 버튼을 추가했습니다.

  파일 불러오기...
  다른 이름 저장...
  주소록에 현재 파일 지정

기본 파일과 주소록 동작
----------------------
- 주소록으로 접속하지 않은 상태:
  ktin_triggers.tin을 편집합니다.

- 현재 주소록의 스크립트가 비어 있는 상태:
  임의의 triggers\ktin_<호스트>_<ID>.tin 파일을 만들지 않습니다.
  ktin_triggers.tin을 기본 파일로 지정하고 sessions.ini에도 기록합니다.

- 현재 주소록에 기존 .tin 파일이 지정되어 있는 상태:
  해당 파일을 편집기로 엽니다.

- 다른 파일을 편집하려면:
  '파일 불러오기...'를 누릅니다. 이 동작만으로 주소록 설정은 바뀌지 않습니다.

- 불러온 파일을 주소록 접속 시 자동으로 읽게 하려면:
  '주소록에 현재 파일 지정'을 누릅니다.

- 새 파일을 만들려면:
  '다른 이름 저장...'을 누른 뒤 .tin 파일명을 지정합니다.

ktin_c_고유번호의 의미
----------------------
ktin_c_DB7B75B9687E83DE 같은 문자열은 파일명이 아닙니다.
한글 폴더를 TinTin++ Class로 묶기 위한 내부 식별자입니다.

화면 표시 폴더 이름: 기본
TinTin++ 내부 Class: ktin_c_DB7B75B9687E83DE

폴더 이름을 한글로 저장하면서도 TinTin++에서 안전하게 그룹을 관리하기 위해
Class 식별자는 영문과 숫자로 생성합니다.

확인 절차
---------
1. 새 ktin.exe를 실행합니다.
2. 편집 -> 트리거 편집을 엽니다.
3. 폴더와 트리거를 추가합니다.
4. 인식 패턴 예:

   [ENTER]를 입력하면 게임에 들어갑니다. :

5. 실행 명령 예:

   #CR

6. '저장 후 다시 읽기'를 누릅니다.
7. TinTin++ 입력창에서 다음을 입력합니다.

   #act

8. 등록된 ACTIONS 목록에 패턴이 표시되는지 확인합니다.
9. 직접 시험하려면 다음을 입력합니다.

   #showme {[ENTER]를 입력하면 게임에 들어갑니다. :}

10. 트리거 동작 추적은 다음 명령으로 확인합니다.

   #debug {actions} {on}

BOM 확인
--------
PowerShell:

  Format-Hex -Path .\ktin_triggers.tin | Select-Object -First 2

정상 파일 첫 바이트:

  23

잘못된 UTF-8 BOM 파일 첫 세 바이트:

  EF BB BF

WSL 또는 Linux:

  xxd -l 16 ktin_triggers.tin

정상 출력은 00000000 위치에서 23으로 시작합니다.

트리거가 목록에는 있으나 실제 서버 문구에서 동작하지 않을 때
-----------------------------------------------------------
로그인 프롬프트처럼 줄바꿈 없이 나뉘어 들어오는 문자열은 서버 패킷 분할의
영향을 받을 수 있습니다. 먼저 #act에 트리거가 실제 등록되었는지 확인합니다.
등록되어 있다면 TinTin++에서 다음 값을 시험할 수 있습니다.

  #config {packet patch} {0.5}

또는 서버가 GA/EOR 프롬프트를 보내는지 확인합니다.

KTin 2.7.15 - 트리거 폴더 사용 상태 및 상세 화면 색상 수정
================================================================

수정 내용
---------
1. 폴더 또는 트리거를 선택하고 `사용`을 체크하거나 해제하면
   `상세 적용`을 따로 누르지 않아도 왼쪽 트리의 `[켬]/[끔]` 표시가
   즉시 갱신됩니다.

2. 상위 폴더가 꺼져 있으면 하위 폴더와 트리거의 개별 `사용` 값이
   켜져 있어도 실제로는 실행되지 않으므로 트리에는 `[끔]`으로 표시합니다.
   상위 폴더를 다시 켜면 각 하위 항목의 원래 개별 설정이 복원됩니다.

3. 상세 편집 영역만 흰색으로 보이던 이유는 Windows의 `BS_GROUPBOX`
   컨트롤이 일부 테마에서 내부 배경을 흰색으로 직접 그렸기 때문입니다.
   해당 컨트롤을 현재 KTin 테마 배경을 사용하는 프레임으로 교체했습니다.

4. `ktin_c_DB7B75B9687E83DE` 같은 값은 파일명이 아닙니다.
   한글 폴더를 TinTin++ Class로 묶기 위한 내부 식별자입니다.
   실제 편집 파일은 창 맨 위 `편집 파일`에 표시됩니다.

5. 주소록에 별도 스크립트 파일이 지정되지 않았으면 기본 편집 파일은
   `ktin_triggers.tin`입니다. 다른 파일은 `파일 불러오기...`로 열고,
   `다른 이름 저장...`으로 새 파일을 만들 수 있습니다.

확인 절차
---------
1. 편집 -> 트리거 편집을 엽니다.
2. 폴더 안에 트리거를 하나 만들고 두 항목을 모두 `사용`으로 둡니다.
3. 폴더를 선택하여 `사용` 체크를 해제합니다.
4. 폴더와 내부 트리거가 모두 즉시 `[끔]`으로 표시되는지 확인합니다.
5. 폴더를 다시 켜면 내부 트리거가 원래 개별 설정대로 `[켬]`으로
   돌아오는지 확인합니다.
6. 상세 편집 영역이 나머지 창과 같은 어두운 배경으로 표시되는지 확인합니다.
